# MyGrokBot — Telegram-мост к Джарвису (Grok Bot)

Личный Telegram-бот, который работает локально на Маке и связывает тебя с Grok Bot:
пишешь задачу боту в Telegram → бот передаёт её Grok Bot через вебхук → Grok Bot
выполняет задачу (в том числе на этом Маке) и кладёт ответ в папку → бот присылает ответ в чат.

## Как это работает

```
Telegram ──► бот (aiogram, long polling)
               │  1. копит сообщения MESSAGE_DEBOUNCE_SECONDS (альбом, фото + текст → одна задача)
               │  2. сохраняет задачу (task_id → chat_id) в runtime/tasks.sqlite3
               │  3. отвечает «Принял, работаю…» и показывает «печатает…»
               │  4. скачивает вложения в runtime/inbox/<task_id>/
               │  5. POST WEBHOOK_URL  {"task_id", "chat_id", "text", "outbox_dir", ...}
               ▼
           Grok Bot (регулярная задача, запускается вебхуком)
               │  выполняет задачу и пишет в runtime/outbox/:
               │    <task_id>.progress.txt  промежуточный статус (сколько угодно раз)
               │    <task_id>.png           картинка (необязательно)
               │    <task_id>.files/        любые файлы в ответ (необязательно)
               │    <task_id>.buttons.json  кнопки-варианты (необязательно)
               │    <task_id>.txt           текст ответа — сигнал «готово», пишется последним
               ▼
бот каждые OUTBOX_POLL_SECONDS проверяет runtime/outbox,
отправляет ответ в нужный чат и переносит файлы в runtime/sent/
```

- Писать задачи могут только ID из `ALLOWED_USER_IDS`; остальные игнорируются и пишутся в лог
  (это касается и нажатий кнопок).
- Понимает текст, голосовые, аудио, кружки, фото (и альбомы), документы, видео, GIF, стикеры,
  геолокацию, контакты и пересланные сообщения. Расшифровку голосовых делает Grok Bot по пути к файлу.
- **Reply** на любое сообщение бота (или на своё сообщение с задачей) продолжает ту задачу:
  в вебхук уходит `parent_task_id`.
- Если ответа нет `TASK_TIMEOUT_MINUTES` минут, бот один раз предупреждает, что задача ещё в работе
  или могла зависнуть, и перестаёт показывать «печатает…». Поздний ответ всё равно будет доставлен.
- Ответы с Markdown (`**жирный**`, `*курсив*`, `` `код` ``, блоки кода, ссылки, заголовки, списки,
  цитаты) показываются с форматированием; если Telegram не принял разметку, ответ уходит обычным текстом.
  Длинные ответы режутся на сообщения до 4096 символов по абзацам.
- Если ответ лежит в outbox, а задачи с таким `task_id` нет в базе, он уходит первому ID из
  `ALLOWED_USER_IDS` — так Grok Bot может сам написать тебе (например, уведомление).
- Если ответ не удаётся отправить 5 раз подряд, файлы переносятся в `runtime/failed/`.
- Если вебхук недоступен, бот делает несколько попыток с нарастающей паузой и сообщает об ошибке в чат.
- Раз в `CLEANUP_INTERVAL_HOURS` часов удаляется всё в `runtime/sent`, `runtime/failed`, `runtime/inbox`
  и ротированные логи `logs/*.log.N` старше `CLEANUP_MAX_AGE_DAYS` дней. База задач не чистится.

### Команды

| Команда            | Что делает                                                              |
|--------------------|-------------------------------------------------------------------------|
| `/start`           | Приветствие и подсказка                                                 |
| `/tasks`           | Задачи в работе: id, сколько висит, начало текста                       |
| `/cancel`          | Отменить последнюю задачу в работе                                      |
| `/cancel <id>`     | Отменить конкретную задачу                                              |
| `/status`          | Жив ли бот, аптайм, сколько задач в работе, настроен ли вебхук          |
| `/id`              | Присылает твой Telegram ID (работает для всех — чтобы узнать ID)        |

`/cancel` помечает задачу отменённой только в боте (у Grok Bot нет отдельного канала отмены):
промежуточные статусы и таймаут для неё больше не показываются, а если ответ всё же придёт,
он будет доставлен с пометкой «(Ответ на отменённую задачу …)».

## Протокол для Grok Bot

### Вебхук: что присылает бот

`POST WEBHOOK_URL`, `Content-Type: application/json`, ключ в заголовке `WEBHOOK_AUTH_HEADER`.
Обязательные поля не изменились с первой версии; новые поля добавляются только когда есть данные.

```json
{
  "task_id": "20261028-213000-a1b2c3",
  "chat_id": 5194842887,
  "text": "[Переслано от Иван (@ivan)]\nЧто на этом скриншоте?",
  "outbox_dir": "/Users/semensaifutdinov/CursorProjects/MyGrokBot/runtime/outbox",

  "files": [
    {
      "type": "photo",
      "path": "/Users/semensaifutdinov/CursorProjects/MyGrokBot/runtime/inbox/20261028-213000-a1b2c3/01-photo.jpg",
      "caption": "Что на этом скриншоте?",
      "file_name": null,
      "mime_type": null,
      "file_size": 183204
    },
    {
      "type": "voice",
      "path": "/Users/semensaifutdinov/CursorProjects/MyGrokBot/runtime/inbox/20261028-213000-a1b2c3/02-voice.oga",
      "caption": null,
      "file_name": null,
      "mime_type": "audio/ogg",
      "file_size": 9821,
      "duration": 6
    }
  ],
  "parent_task_id": "20261028-212843-f66b4a",
  "reply_to_text": "Текст сообщения, на которое ответили (до 1000 символов)",
  "button": {"text": "Да, запускай", "value": "yes"}
}
```

| Поле             | Когда есть                         | Что значит                                                                 |
|------------------|------------------------------------|----------------------------------------------------------------------------|
| `task_id`        | всегда                             | id задачи, им называются файлы ответа                                      |
| `chat_id`        | всегда                             | чат Telegram                                                               |
| `text`           | всегда (может быть `""`)           | текст или подписи всех сообщений пачки через пустую строку; пересланные — с пометкой `[Переслано от …]`; геолокация, контакт, стикер — текстом в `[…]` |
| `outbox_dir`     | всегда                             | куда класть ответ                                                          |
| `files`          | есть вложения                      | массив файлов, см. ниже                                                    |
| `parent_task_id` | reply на сообщение задачи или нажата кнопка | задача, которую продолжает эта                                     |
| `reply_to_text`  | пользователь ответил reply         | текст процитированного сообщения                                           |
| `button`         | нажата кнопка                      | какая кнопка нажата; `text` задачи = `button.value`                        |

Элемент `files`: `type` — `photo`, `document`, `video`, `animation`, `sticker`, `voice`, `audio`,
`video_note`; `path` — абсолютный путь на Маке (или `null`, если скачать не удалось, тогда есть `error`);
`caption`, `file_name`, `mime_type`, `file_size` — из Telegram (могут быть `null`); `duration` (секунды) —
для голосовых, аудио, видео. Файлы больше `MAX_DOWNLOAD_MB` (и больше 20 МБ — лимит Bot API) не скачиваются.

### Ответ: что кладёт Grok Bot в `outbox_dir`

Порядок важен: всё необязательное — **до** `<task_id>.txt`. Появление `.txt` = ответ готов.

| Файл                       | Обязательно | Что делает бот                                                          |
|----------------------------|-------------|-------------------------------------------------------------------------|
| `<task_id>.progress.txt`   | нет         | Пока задача в работе: заменяет текст «Принял, работаю…» на `⏳ <текст>`, файл удаляет. Можно писать много раз |
| `<task_id>.png` / `.jpg`   | нет         | Картинка; короткий текст (≤1024) уходит её подписью, если нет `.files/` |
| `<task_id>.files/`         | нет         | Папка с любыми файлами: `.png/.jpg/.jpeg` — фото (несколько — альбомом), `.mp4/.mov` — видео, остальное — документами. Скрытые файлы пропускаются |
| `<task_id>.buttons.json`   | нет         | Inline-кнопки под последним сообщением ответа                           |
| `<task_id>.txt`            | да          | Текст ответа (Markdown). Можно пустым, если есть файлы                  |

Порядок отправки: `<task_id>.png` → файлы из `.files/` → текст (кнопки под последним сообщением).
После отправки всё переносится в `runtime/sent/`.

Формат `<task_id>.buttons.json` (любой из вариантов, до 24 кнопок):

```json
["Да", "Нет"]
```
```json
[{"text": "Да, запускай", "value": "yes"}, {"text": "Нет", "value": "no"}]
```
```json
{"buttons": [["Да", "Нет"], ["Отмена"]]}
```

Плоский список до 3 кнопок — один ряд, больше — по кнопке в ряд; вложенные списки — явные ряды.
Нажатие (одно на ответ — остальные кнопки гаснут) создаёт **новую задачу** с `text` = `value`
(или `text`, если `value` нет), `parent_task_id` = исходная задача и полем `button`.

## Установка

Нужен Python 3.12 и [uv](https://docs.astral.sh/uv/).

```bash
cd ~/CursorProjects/MyGrokBot
uv venv .venv --python 3.12
uv pip install --python .venv/bin/python -r requirements.txt
# для разработки и тестов:
uv pip install --python .venv/bin/python -r requirements-dev.txt
cp .env.example .env   # и заполнить значения
```

## Настройка `.env`

| Переменная               | Описание                                                          |
|--------------------------|-------------------------------------------------------------------|
| `BOT_TOKEN`              | Токен бота от @BotFather (обязательно)                            |
| `ALLOWED_USER_IDS`       | Разрешённые Telegram ID через запятую                             |
| `WEBHOOK_URL`            | URL вебхука регулярной задачи Grok Bot                            |
| `WEBHOOK_KEY`            | Ключ вебхука                                                      |
| `WEBHOOK_AUTH_HEADER`    | Заголовок для ключа, по умолчанию `Authorization`                 |
| `WEBHOOK_AUTH_SCHEME`    | Схема, по умолчанию `Bearer`; `none` — передавать ключ как есть   |
| `WEBHOOK_TIMEOUT_SECONDS`| Таймаут запроса, по умолчанию 15                                  |
| `WEBHOOK_MAX_ATTEMPTS`   | Количество попыток, по умолчанию 3                                |
| `OUTBOX_POLL_SECONDS`    | Как часто проверять outbox, по умолчанию 2                        |
| `REPLY_FORMAT`           | `markdown` (по умолчанию) или `plain` — форматирование ответов    |
| `TYPING_INDICATOR`       | Показывать «печатает…», пока задача в работе, по умолчанию `true` |
| `TASK_TIMEOUT_MINUTES`   | Через сколько минут предупредить о долгой задаче, по умолчанию 15; `0` — выкл. |
| `MESSAGE_DEBOUNCE_SECONDS` | Пауза для склейки сообщений в одну задачу, по умолчанию 2.5; `0` — выкл. |
| `MAX_DOWNLOAD_MB`        | Максимальный размер скачиваемого вложения, по умолчанию 20        |
| `CLEANUP_MAX_AGE_DAYS`   | Возраст для чистки sent/failed/inbox и старых логов, по умолчанию 14; `0` — выкл. |
| `CLEANUP_INTERVAL_HOURS` | Как часто запускать чистку, по умолчанию 6                        |
| `LOG_LEVEL`              | Уровень логов, по умолчанию `INFO`                                |

Свой Telegram ID проще всего узнать так: запусти бота с пустым `ALLOWED_USER_IDS`,
отправь ему `/id`, впиши полученное число в `.env` и перезапусти.

## Запуск

```bash
.venv/bin/python -m grok_bridge
# или
./scripts/run.sh
```

Логи пишутся в консоль и в `logs/bot.log` (с ротацией).

### Автозапуск (launchd)

Пример лежит в `deploy/com.semenkulikov.mygrokbot.plist`, инструкция по установке — внутри файла.
Перезапуск после обновления кода: `launchctl kickstart -k gui/$(id -u)/com.semenkulikov.mygrokbot`.

## Тесты

```bash
.venv/bin/python -m pytest
```

## Структура

```
grok_bridge/
├── __main__.py              # точка входа, сборка зависимостей
├── config.py                # настройки (pydantic-settings, .env)
├── logging_setup.py         # консоль + logs/bot.log
├── storage.py               # SQLite: задачи, связь сообщений с задачами, кнопки (с миграцией схемы)
├── bot/
│   ├── handlers.py          # /start, /tasks, /cancel, /status, /id, приём задач и нажатий кнопок
│   └── middlewares.py       # доступ только для ALLOWED_USER_IDS
└── services/
    ├── task_service.py      # создание задачи: «Принял…», вложения, parent_task_id, вебхук
    ├── attachments.py       # вложения Telegram → runtime/inbox/<task_id>/
    ├── batcher.py           # склейка сообщений подряд (debounce)
    ├── webhook_client.py    # отправка задач на вебхук (aiohttp, ретраи)
    ├── outbox_watcher.py    # доставка ответов, статусы, «печатает…», таймауты
    ├── buttons.py           # формат buttons.json и inline-клавиатура
    ├── formatting.py        # Markdown → HTML Telegram
    └── janitor.py           # чистка старых файлов и логов
```
